## 1. 文档说明与设计结论

### 1.1 文档状态与阅读方式

- 版本：v1.0；日期：2026-11-18；状态：研发落地版定稿。新增模型、接口、状态与阈值仍为设计提案，代码实现以任务批次为准。
- 目标：为消费级 UGC 长内容平台建设以作者为中心的工作台，支持数据看板、在线写作、素材与灵感、AI 写作与插图生成；传统写作、AI 辅助写作、纯 AI 写作三种模式并存。
- 阅读顺序：产品／设计读 §1、§3、§4、§8；后端与前端研发读 §2、§6、§12、§13；AI 工程读 §8–§11；测试读 §17；法务与安全读 §2.2、§14、§18。
- 本次仅编写文档，不修改代码、数据库、现有契约、权限、生产配置或供应商账户；不创建真实 AI 任务、不产生模型费用、不提交或部署。
- 现状基点：HEAD `aa58de3` 及 2026-11-18 工作区。现有前端优化、T36 后端工作和 12～14 规划文档尚未提交，必须保留，不能覆盖。
- 文档关系：[12-产品愿景](12-产品愿景与长期迭代规划.md)定义长期方向，[13-执行清单](13-待完成事项与里程碑执行清单.md)定义全项目待办，[14-架构演进](14-多形态内容架构与工程演进规划.md)定义共用底座；本文细化作者场景，不替换它们。

### 1.2 核心设计决定

1. 统一作品、章节、草稿、版本和发布链，三种模式不建立三套互不相通的作品库。
2. 模式决定后续编辑与AI介入方式，不改写已有文本来源、署名、版权或审核状态。
3. 传统模式不自动向模型发送正文；辅助模式以作者选区和明确指令为单位；纯AI模式以受控workflow驱动多个职责明确的Agent生成候选稿。
4. 纯AI不是无人监管出版：可以自动规划、撰写、校验和有限返工，作者必须确认最终候选内容；提交审核与公开发布仍经现有业务服务。
5. 长期记忆以关系型存储的版本化事实、情节事件和来源为权威；向量检索与摘要仅为可重建索引，不以聊天记录或向量相似度当事实真相。
6. 未接受的AI候选稿不会进入正式创作记忆；作者修订旧章后，相关摘要、事实和后续生成必须可识别失效。
7. 数据看板如实显示未接入、处理中和无数据；收益未启用时不显示虚构零收益或模拟曲线。排名、读者分析不泄漏其他作者或读者身份。
8. 先把传统编辑保存、章节选择、状态回读和契约对齐做好，再逐层启用AI；基础设施、版权、未成年保护和费用门禁不会因新增模式而降低。

### 1.3 P0／P1／P2的解释

本文优先级是“作者工作台专项内的交付顺序”，不是对全项目阶段重新命名：

| 专项优先级 | 含义 | 与全项目阶段关系 |
| --- | --- | --- |
| P0 | 可靠作者闭环：私有作品、选章写作、自动保存、冲突恢复、送审与结果 | 主要承接全项目P0；未满足正式身份与生产门禁不得公开上线 |
| P1 | 作者效率与基础洞察：素材灵感、真实看板、AI辅助、受控插图候选、纯AI最小纵向试点 | 多数承接全项目P1或AI独立专项；不自动启用收费和社区 |
| P2 | 长篇纯AI增强、复杂协作、完整收益／排名、互动管理和高级导出 | 服从全项目P2、商业化或社区专项门禁 |

纯AI最小闭环必须进入P1研发与验收范围，不作为一句“未来支持”的空占位；P2只扩大长篇规模、优化质量与效率。功能优先级不代表安全、版权、审计或记忆一致性可以后补。

### 1.5 非目标与明确不做

以下为首版作者工作台明确不做的事项，避免研发把“可扩展”误读为“本期范围”：

- 不做多人实时协作、共享账号共写或团队空间；作者只访问本人作品及明确授权范围。
- 不做无人值守自动发布：纯 AI 只产出候选，必须作者确认，仍走既有审核与公开链路。
- 不做公开素材市场、整本小说抓取、洗稿改写或规避侵权检测的工具。
- 不做跨作品记忆借用、跨作者数据比较或读者身份导出。
- 不做正文富文本块与内嵌排版（P0 保持纯文本）；正文插图待 P2 图文协议与阅读器改造。
- 不做交易、提现、积分兑换或作者余额账户；收益只读正式账本投影。
- 不把审核员、运营、财务工作台并入作者导航，也不授予作者审核终裁权。
- 不展示模型内部思维链、供应商密钥、风控阈值或其他作品资料。
- 不以“AI 检测分数”作为版权裁决或处罚依据。

### 2.2 继承的边界

- 作者只访问本人作品及明确授予的范围；本专项首版不引入共享账号或多人实时协作。
- C0／C1／C4不得公开出版；C2公开出版须有效监护同意，并保留原禁止商业化及其他未成年限制。AI创作可用年龄、供应商数据处理与收费资格另行批准，不因有写作权限自动获得AI权限。
- 工作台可以解释审核状态、提交申诉，不能授予作者审核员权限或平台终裁权。
- 作品元数据、封面、正文、未来插图都需受版本和审核控制；新候选不会覆盖旧公开版本。
- 商业化未启用前收益区域隐藏或显示“收益功能未启用”，不提供交易、提现、积分兑换入口。
- 数据与核心素材境内处理要求继续有效；外部供应商、存储地域、保留与训练条款在调用前核查。

## 3. 用户任务、模块与职责

### 3.1 主要作者任务

| 场景 | 作者目标 | 成功结果 |
| --- | --- | --- |
| 首次创作 | 建作品、建第一章、保存并确认送审 | 不丢稿，知道草稿、待审与公开的差别 |
| 日常连载 | 找到上次编辑位置并持续更新 | 少导航、稳定自动保存、章节顺序正确 |
| 修订旧章 | 调整内容但不破坏读者正在读的版本 | 新修订单独送审，旧公开版保持合法可见 |
| 取材 | 收集设定、资料、灵感，标记可用范围 | 以后找得到来源，不把参考材料误当原创正文 |
| 辅助创作 | 改写、续写、起名、校对或生成图片 | 可预览、可拒绝、可比较，作者始终控制正文 |
| 纯AI创作 | 给出方向与边界，让系统生成完整候选章节 | 能理解计划、费用、进度、记忆与冲突，确认后接入草稿 |
| 复盘作品 | 判断阅读、收藏、章节表现与收入变化 | 口径明确、数据可信、没有越权明细 |

### 3.2 模块边界

| 模块 | 拥有职责 | 输入／输出 | 明确不负责 |
| --- | --- | --- | --- |
| 作者概览／数据看板 | 私有作品指标、时间筛选、趋势、导出入口 | 指标快照、统计窗口、结果状态 | 修改交易账本、跨作者后台分析、公开排名运营 |
| 作品与章节 | 作品选择、元数据、章节组织、生命周期 | work／chapter／draft／workflow | 审核终裁、直接修改公开正文 |
| 写作编辑器 | 输入、自动保存、历史恢复、差异合并、预览与送审 | 纯文本及草稿revision | 自行判断最终适龄、发布或版权有效 |
| 素材库 | 私有资料、标签、出处、许可、引用范围 | 文本笔记、合规图片、受控附件引用 | 开放盗版抓取、下载任意外链、公开素材市场 |
| 灵感箱 | 轻量记录、主题归档、转设定／转提纲 | 作者笔记及显式转化操作 | 自动变成小说正典或自动提交审核 |
| AI辅助面板 | 指令、授权上下文、候选、差异接受、来源 | 快照＋限定请求→候选artifact | 静默改写、后台自动发送整本作品 |
| 纯AI工作流 | 计划、分工、检查点、有限返工、预算与恢复 | 冻结任务输入→待确认候选包 | 直接写业务库、审批自己输出、无限自循环 |
| 长期记忆 | 世界观／人物／情节／伏笔与来源版本 | 确认事实、修订、冲突、失效 | 把模型推测当事实、跨作品借用私密内容 |
| AI插图 | 场景与角色参考、生成、选图、权利记录 | 授权描述／素材→隔离图片候选 | 自动公开未经审核图片、承诺版权必然成立 |
| 读者反馈（后续） | 本人作品评论查看、回复、举报、屏蔽申请 | 社区域授权视图与动作 | 平台删评终裁、批量读者身份导出 |
| 作者设置 | 默认模式、编辑偏好、AI许可与预算 | 用户偏好和能力开关 | 角色授权、降审核门槛、关闭平台安全护栏 |

支持键盘章节切换、编辑、预览、候选比较、接受与取消；按钮有明确名称。200%文字缩放与320px窄屏不遮挡保存状态；长标题、长正文和中文输入法组合期间不打断输入。业务状态播报集中管理，避免多个live region重复朗读。

### 4.8 端到端用户旅程与交互流程

每条旅程给出主路径与关键异常分支，作为交互验收与接口编排的共同依据；图中 `AW-xx` 指 §4.1 的页面。

**J1 首次创作（AW-02 → AW-04 → AW-05）**

1. AW-02 新建作品：填标题、简介、分类、标签、封面（可选）→ 创建 WORK 草稿，作品业务态为草稿。
2. AW-03 点“写第一章”：服务端在作品行锁下原子取号创建 chapter，同时创建章节草稿。
3. AW-04 输入标题与正文；停止输入 2 秒自动保存，状态栏显示 CLEAN／DIRTY／SAVING。
4. 点“预览”：冻结当前服务端快照，展示作品、章节、字数、内容来源声明与素材许可状态。
5. 点“提交审核”：带 If-Match 与幂等键提交 → 202 受理；草稿转 SUBMITTED，生成不可变版本与发布流程。
6. AW-05 回读流程状态：机审 → 人审 → 通过／驳回；结果同步到通知与作品页。
7. 异常：保存失败保留本地稿并重试；预览后正文变化则预览失效；驳回后按原因新建修订，不直接改已提交版本。

**J2 日常连载与恢复（AW-01 → AW-04）**

1. AW-01 显示“最近编辑”“需作者处理事项”和可用指标摘要。
2. 点“继续写作”：按 workId＋chapterId＋draftId 读取服务端最新 revision，不以本地缓存作为真相。
3. 编辑器恢复上次光标附近的滚动位置（本机 UI 偏好，跨设备不承诺）。
4. 写作中串行自动保存；断网转 OFFLINE 并提示未同步，可选本机恢复。
5. 切换章节或离开页面前等待在途保存；仍有未保存修改时拦截并给出保存／放弃选项。
6. 异常：412 进入三方比较；428 视为协议错误并回读；403（账号变化）停止上传并清理旧身份视图。

**J3 修订旧章（AW-05 → AW-04）**

1. AW-05 选择已公开章节 → “创建修订”。
2. 系统以当前公开版本为 base 创建新草稿，公开版本不被原地修改。
3. 修改 → 保存 → 预览 → 送审；新版本独立走机审／人审。
4. 通过后公开指针原子交换，读者侧切到新版本；旧版本保留审计与可追溯记录。
5. 异常：审核期间读者继续读旧版；撤回仅限允许状态；下架由治理链路执行，作者不能自审自批。

**J4 取材与灵感（AW-06 → AW-04／AW-07）**

1. AW-06 新建灵感或素材：标题、正文、标签、所属作品（可空）、来源与许可范围。
2. 整理：转为提纲候选、人物设定候选或世界资料；引用不自动成为正典。
3. 写作时在工具面板引用：插入引用标记，或显式“加入本次 AI 上下文”。
4. 保存时引用清单进入材料快照；送审时材料 hash 固化，供审核核验。
5. 异常：许可缺失禁止外部处理与公开引用；撤权使新任务失效，历史证据按保留策略受控留存。

**J5 AI 辅助改写（AW-04）**

1. 选中段落或指定范围 → 打开 AI 面板 → 选动作（改写／润色／续写／校对）。
2. 首次使用确认供应商、发送范围、用途、保留策略与预算；“开启 AI”不等于永久同意。
3. 服务端创建 ASSISTED 任务并返回 202；面板显示业务步骤与预计费用。
4. 候选返回：差异视图、引用来源与 warnings；可替换、插入或另存备选。
5. 接受：冻结输入、核对全稿 hash 与 baseRevision 后条件替换；拒绝只保留审计，不写正文。
6. 异常：选区已变标 STALE 重新生成；存在 DIRTY 先保存再比较；超预算直接拒绝并说明上限。

**J6 AI 插图（AW-06／AW-08）**

1. 选场景或角色 → 选已确认设定与合法参考图 → 选用途（私有素材／封面候选）。
2. 展示供应商与预算 → 生成 → 结果隔离 → 类型、像素、hash、净化与内容检查。
3. 候选图库中选图 → 确认来源与许可 → 入私有素材资产。
4. 封面：作者修改 WORK 草稿的封面引用 → 送审；正文插图待 P2 图文协议后启用。
5. 异常：未授权真人形象、违法或性化未成年内容一律拒绝；供应商临时 URL 不得直接当公开封面。

**J7 纯 AI 单章（AW-08 → AW-04／AW-05）**

1. AW-08 新建任务：选章（可为空章）、章节目标、故事截止点、引用素材、预算上限、修订轮数。
2. 服务端校验归属、模式、草稿与记忆基线、许可与预算 → 202 → QUEUED／RUNNING。
3. 页面显示计划与业务步骤（不展示模型内部思维链），可暂停、取消。
4. 检查发现冲突 → WAITING_DECISION（作者选择）或 WAITING_AUTHOR（等待最终确认）。
5. 候选包：正文差异、冲突清单、引用事实、记忆 delta、实际费用与未决问题。
6. 作者接受 → 原子写草稿＋来源＋记忆提交；或“接管编辑”切模式；或拒绝。
7. 异常：基线变化标 STALE；预算耗尽停止且不跳过检查；旧世代结果不得覆盖新模式草稿。

**J8 看板复盘与导出（AW-03）**

1. 选择作品（单部／全部本人）、时间范围与日／周／月分桶。
2. 请求携带筛选摘要；响应含 summary、series、asOf、completeness。
3. 切换阅读／收藏／收益指标；与上一周期对比时采用同等已过时长。
4. 导出：异步任务冻结筛选与指标版本，24 小时内有效，下载时重新鉴权并审计。
5. 异常：未接入显示 UNAVAILABLE 而非 0；迟到响应按请求世代丢弃；导出文本做公式注入防护。

**J9 读者反馈处理（AW-09）**

1. 未读列表 → 打开评论原文 → 回复、举报或申请屏蔽。
2. 回复有长度与敏感提示；举报进入治理流程，不即时删评。
3. 处理状态回写；审核与治理结果通过通知返回作者。
4. 异常：评论已删除提示失效；越权访问 404；批量导出读者身份不提供。

### 5.2 筛选与图表

支持单作品／全部本人作品、最近7／30／90天、自定义日期及按日／周／月分桶。首版自定义最长366天、图表最多366点；超限返回明确校验，不默默截断。需更长历史时转异步导出或后续分层存储方案。

每个请求绑定筛选摘要与请求世代；快速切日期时迟到响应不可覆盖新结果。默认选择阅读趋势，可切收藏与收益；不同量纲不强塞同一坐标轴。悬浮提示包含日期、单位、值及是否完整桶，移动端用点选。

收藏总数、排名是时点值，趋势取每桶末快照；阅读次数、净增是流量值，可按桶求和；区间UV需重新去重或受控聚合，不能相加。累计值与周期值在字段和UI上分开。

### 5.3 排名设计与防误导

首版优先消费已有合规排名快照，尚无排名服务则显示未启用。候选规则可采用有效阅读、持续阅读、真实收藏变化的多维评分，规则权重、样本门槛、更新频率、反作弊和并列名次策略须平台专项批准；本文不虚构已确定公式。

作者只能查看本人作品名次与公开榜已允许信息，不获得其他作品的私有收入、阅读明细或风控分数。榜单范围按品类、时间、公开资格定义；不同创作模式是否分榜进入决策，不默认把AI批量产量计入热度。未成年不适用的商业激励、行为画像或消费刺激不能借作者看板开放。

### 5.4 数据流水线与导出

业务事件／账本事实 → 幂等聚合 → 日指标与快照 → 区间查询 → 作者DTO。响应包含metricVersion、asOf、timezone、completeness、series、summary；completeness区分COMPLETE／PARTIAL／UNAVAILABLE，不把未知转0。

迟到事件首版按48小时滚动校正的候选窗口设计，退款与账务调整按真实业务发生和入账规则处理，不受分析窗口吞掉。窗口外校正需版本化修订并标注历史变更，不静默覆盖财务事实。

导出仅本人授权汇总数据，CSV／XLSX为后续选型；先CSV即可。异步任务冻结筛选与指标版本，下载24小时失效，下载时重新鉴权并审计；防CSV公式注入，对`= + - @`开头的文本采用安全导出编码。禁止读者个人身份、完整评论敏感证据或其他作者明细导出。

## 6. 写作中心与草稿可靠性

### 6.1 作品与章节管理

新建作品按现有WORK草稿保存标题、简介、分类、标签和封面引用；作品元数据送审不等于章节自动公开。作者可以看本人私有作品与章节，包括未发布项，使用现有私有列表接口而非公开书城接口。

章节必须按稳定chapterId选择。新建取号由服务端在聚合根锁／唯一约束下完成，前端不能把数组长度当序号。首版只支持新增、选择、查看状态和修改EDITABLE草稿；拖拽重排、分卷、定时发布需要新增模型与契约后启用，不能直接改历史序号。

已提交草稿只读；需要修改时按现有工作流允许操作取消或从合法版本创建新修订，不对SUBMITTED记录PUT正文。公开版本不存在直改入口。

### 6.2 编辑器内容模型

P0保持纯文本编辑，支持段落、撤销重做、查找替换、字数、专注模式和章节预览；标题与正文分开。浏览器显示换行与服务端文本一致，不把HTML富文本或内联图片地址塞进body。

契约规定非空正文1～100000字符，同时遵守现有请求与UTF-8字节预算；中文字符数、UTF-16长度和字节数不同，前后端统一计量与边界测试。中文输入法组合事件结束后再触发保存节流，不中断候选输入。

空章节壳可存在，但现有正文草稿契约不接受空字符串。空白输入阶段标“尚未保存正文”，首次有合法标题／正文后才创建草稿；清空已存在正文时保留本地待编辑状态，不伪称云端已清空。若要允许空正文服务端草稿，必须另改契约，不能隐式放宽。

纯AI从空章启动不要求先创建空草稿：新增章节级creation_session，绑定workId／chapterId，draftId及baseRevision为空，并冻结sessionRevision与expectedNoEditableDraft=true。任务只生成隔离候选；作者接受时在同一章节锁下再次确认不存在EDITABLE稿，再原子创建符合原契约的非空草稿、绑定会话、写来源与记忆。人工首次建稿也必须取得同一章节锁并推进sessionRevision；先有人建稿时旧空章候选不能覆盖或再建第二份稿，须进入显式比较／新任务流程。不得用空格或占位正文绕过非空契约。

### 6.3 自动保存协议

首版候选策略：有效输入停止2秒后保存，连续编辑最长15秒触发一次保存，手动保存立即排队；同一草稿同时只发一个保存请求。队列只保留最新快照，当前请求完成后若仍脏继续保存，禁止并发乱序PUT覆盖。

保存请求使用读取到的带引号ETag／If-Match。保存返回新revision和ETag，客户端只更新对应快照基线；发送期间的新输入仍保留为脏。保存成功消息包含服务端确认时间，不用“请求已发出”代表成功。

保存状态：CLEAN（已确认）、DIRTY（本地变更）、SAVING、OFFLINE、CONFLICT、ERROR；这些是客户端状态，不写入现有draft.state。状态栏只展示必要中文及恢复动作。

| 场景 | 行为 | 禁止行为 |
| --- | --- | --- |
| 请求超时结果未知 | 回读草稿revision与内容hash核对；已写入则确认，否则用新基线恢复保存 | 盲重试旧版本并报丢稿，或无条件覆盖 |
| 412版本冲突 | 暂停自动保存，三方比较base／local／remote；作者选合并后按最新ETag保存 | 自动取最后写入或丢弃本地文本 |
| 428缺版本 | 标为客户端协议错误，阻止继续写入并回读 | 去掉If-Match绕过服务端 |
| 403／账号变化 | 停止上传与AI任务新动作，清除旧身份视图，保留受控恢复提示 | 将旧账号草稿保存到新账号 |
| 网络离线 | 保持内存编辑，显示“未同步”；可选本机恢复需明确授权 | 默认承诺永久离线保存 |
| 400正文超限 | 定位字数／字节问题，保留本地内容，允许导出作者自身文本备份 | 截断后静默保存 |

本机恢复首版为显式开启的便利能力，不等于离线阅读产品。可用浏览器持久化存储按主体／作品／草稿分区，退出登录清理、默认7天过期、共享设备提醒；浏览器存储不应宣称能防同源脚本或设备持有人。未开启时刷新／关闭前提示可能丢失未同步内容，不能依赖unload最后一跳保证保存。

### 6.4 历史与恢复

草稿保存是可变工作记录，需另有受控revision快照用于冲突与恢复。建议保留最近30天且最多200个自动检查点，提交、模式切换、候选接受前后的关键点另按已批准保留规则保留；快照可能含私稿，不能写进普通审计正文。

恢复操作生成一个新的草稿revision，不让revision倒退、不修改已提交content_version。历史选择、差异预览、确认恢复三步完成；有AI运行时恢复会使其输入基线失效，需要先冻结接受入口并按模式切换屏障处理。

### 6.5 送审流程

编辑 → 保存成功 → 预览冻结快照 → 显示作品／章／版本、生成内容声明、封面与素材许可状态 → 作者确认 → 带If-Match及幂等键提交 → 202受理 → 工作流状态回读。

预览后正文再变化则预览过期；提交不能用未保存的本地文本替代服务器草稿。重复点击共享同一幂等请求身份，返回同一提交结果；同键改载荷拒绝。

纯AI来源也需作者确认最终稿和必要的AI标识，但作者确认不替代平台机审／人审。拒绝、暂停、撤销与公开分别显示，不能把“提交成功”写成“发布成功”。

## 7. 素材库与灵感箱

### 7.1 条目类型与范围

| 类型 | 核心字段 | 使用方式 |
| --- | --- | --- |
| 灵感笔记 | 标题、纯文本、标签、所属作品可空、状态 | 收集→整理→转提纲或设定候选 |
| 世界资料 | 文本摘录、出处、引用位置、许可说明 | 仅在许可范围内参考；摘录不是原创正典 |
| 人物参考 | 外貌／性格参考、角色关联、出处、图片asset引用 | 与正式人物设定分开，避免参考现实人物直接公开 |
| 场景／情节卡 | 场景目的、冲突、参与人物、时间线候选 | 转章节计划前确认 |
| 图片素材 | 私有资产、尺寸、净化hash、来源、许可、到期 | 作为已授权生成参考或封面候选 |

素材默认私有；作者全局库与作品内库分开。AI上下文只使用明确加入本次请求的条目或作者批准的作品可用集合，不遍历全部账号资料。

### 7.2 来源与许可

每条可供AI或公开引用的素材记录来源类型（作者原创／合法授权／公共领域主张／外部引用）、出处文字或用户提供链接、作者声明、凭据受控引用、允许用途、到期时间与复核状态。声明未知不自动变为“可训练／可商用”。

首版不自动抓取外链、不爬整本小说；作者可保存链接和自己的笔记。后续引入URL导入时需SSRF防护、域名／体积／类型限制与版权评审；用户粘贴网页指令不得成为Agent系统指令。

### 7.3 灵感转化

灵感可以生成“提纲候选”，作者选择接受后形成outline_revision；可以申请加入人物／世界观记忆，但要确认实体、事实、故事时间、知情范围及来源。任何自动分类和标签均可改，不能以标签推导用户同意外部模型处理。

删除素材先撤销新引用权限，标记引用中的任务失效；历史发行证据根据法律保全与保留策略受控保留。新AI任务不能继续使用已撤权素材，向量索引与缓存也需失效。

## 8. 三种创作模式

### 8.1 模式定义与行为矩阵

| 维度 | 传统写作MANUAL | AI辅助ASSISTED | 纯AI写作AUTONOMOUS |
| --- | --- | --- | --- |
| 作者角色 | 直接撰写正文 | 直接撰写并按需请求建议 | 制定创作目标、约束、计划并确认候选 |
| 编辑器 | 完整可编辑 | 完整可编辑，旁边展示候选差异 | 任务运行期间候选区只读；接管后切模式编辑 |
| AI介入 | 默认无正文模型调用 | 选区／明确段落／指定上下文，单项任务 | workflow按计划调度多Agent、自动检查和有限返工 |
| 正文写入 | 作者保存 | 作者接受候选后条件写入 | 作者接受完整候选包后条件写入 |
| 长期记忆 | 作者手动维护；不自动模型抽取 | 可主动申请提取，候选需确认 | 生成使用冻结记忆，接受时确认新增事实与冲突处理 |
| 费用 | 不产生AI调用费用 | 每次任务显示范围与上限 | 批次及步骤预算、确认执行、实时归集 |
| 发布 | 作者保存、预览、送审 | 同左，保留AI来源标识 | 同左，不自动公开 |
| 内容来源 | 作者输入及已存在来源 | 人工＋AI混合，逐次接受可追溯 | 主要AI生成，人工确认／修改可追溯 |
| 适用场景 | 有稳定写作习惯、隐私敏感 | 局部卡文、校对、改写、构思 | 从大纲到章节的受控自动生产 |

“纯AI”描述主要文本生成方式，不保证没有人的创意贡献，也不表示平台可以替作者作出法律承诺。AI功能被禁用时传统模式仍可用，但原有AI来源事实不会被擦除。

### 8.2 模式作用域

工作台保存账号默认偏好；作品保存默认模式；具体章节的creation_session保存当前有效模式、modeEpoch、sessionRevision和当前draftId（尚未建稿时为空）。新会话继承作品默认，切换当前章节不批量改变其他章节、既有任务或历史内容。

modeEpoch为每次模式切换、接管或需要废止运行基线的单调世代。所有任务绑定workId、chapterId、sessionRevision、draftId及baseRevision（空章二者皆空）、modeEpoch、memoryRevision、sourceEpoch及outlineRevision；旧世代任务即使返回成功也不能覆盖新模式草稿。

首版同一作品只允许一个会写入章节候选或记忆的纯AI批次处于执行／待确认状态。辅助任务可并发生成只读候选，但接受时必须逐一CAS校验；图片任务独立但受相同作品权限与预算约束。

### 8.3 六种切换

| 切换 | 作者操作与确认 | 服务端处理 | 切换后内容 |
| --- | --- | --- | --- |
| MANUAL→ASSISTED | 点击模式，首次确认模型处理范围与预算 | 保存当前稿，检查AI资格，递增世代 | 原文保持；AI面板出现，不自动生成 |
| ASSISTED→MANUAL | 有运行任务时说明取消或保留只读结果 | 停接受旧任务、递增世代、请求取消后续步骤 | 已接受内容保留；未接受结果不可自动写入 |
| MANUAL→AUTONOMOUS | 选择从空稿／现有稿续写，确认提纲、记忆、目标和上限 | 保存快照，检查来源许可与记忆，创建有界计划 | 现有稿保留；候选不直接替换 |
| ASSISTED→AUTONOMOUS | 处理尚未接受的候选，确认新任务范围 | 旧候选保留只读／拒绝，新世代绑定确认基线 | 不把所有建议默认为已接受设定 |
| AUTONOMOUS→ASSISTED | 点击接管，选择原稿或已完成候选作为起点 | 先废止旧接受资格，冻结任务，确认后条件应用选择的候选 | 转可编辑；旧后台结果不得覆盖 |
| AUTONOMOUS→MANUAL | 同上，并关闭后续AI调用 | 停止新调度、递增世代、保存选择结果和来源记录 | 原文／已选择候选可人工编辑，来源仍保留 |

若本地未保存、网络断开或版本冲突，切换不完成，保留原模式与可恢复内容。模式切换不能只改客户端开关；多个标签页必须从服务端看到同一modeEpoch。

### 8.4 切换屏障与原子性

普通切换（不接受候选）：客户端进入统一写入队列，等待在途保存完成并保存合法本地修改 → 服务端锁章节会话并校验sessionRevision及草稿revision → 递增modeEpoch、撤销旧任务接受资格、记录模式事件 → 返回新状态 → 客户端切视图。空章没有合法正文时只校验会话，不创建占位草稿。外部取消异步进行，安全性不依赖供应商立即停止。

“以候选接管”是独立原子命令，不执行普通切换的先保存／先废止步骤：客户端确认本地CLEAN并冻结输入；服务端在旧epoch仍有效时校验候选及全部基线，然后同事务应用正文、来源和作者批准的记忆变化、递增草稿revision与modeEpoch、终结该任务为ACCEPTED并失效其他旧任务。空章按§6.2创建合法草稿。提交成功前不把候选粘入编辑区，不先递增epoch导致候选自我失效。

本地有未保存修改时禁止直接以候选接管：作者可保留修改并先保存，随后旧候选按STALE处理，比较后形成基于新快照的新任务；也可在差异预览后明确放弃本地修改。不能隐式保存后重新给旧候选换基线，更不能静默丢弃修改。仅接管原稿、不接受候选时走普通切换并取消旧任务。

切换后旧任务记录可查看和手动复制为新候选，但再次应用必须新建明确接受动作、重新校验当前基线和权利；不能复用旧接受令牌。

### 8.5 用户体验差异与授权

传统作者不被AI按钮打断，不自动弹生成推荐。辅助作者看到小范围、可比较的改动及来源。纯AI作者看到计划、进展、冲突、费用、记忆变化与最终确认，不被迫管理十几个技术Agent窗口。

首次调用及扩大范围时说明发送哪些正文／素材、给哪类供应商、用途、保留策略及费用；“开启AI”不是永久同意未来任意用途。撤回处理许可立即阻止新调用，已发生调用按合同与供应商删除机制处理并记录，不能声称能抹去已传输数据。

### 8.6 模式切换的交互时序与可见状态

普通切换（不接受候选）的客户端与服务端时序如下；其原子性约束见 §8.4。

| 阶段 | 客户端 | 服务端 | 作者可见 |
| --- | --- | --- | --- |
| 发起 | 点击模式；本地有未保存修改时先给“保存并切换／放弃修改／取消” | — | 明确说明将要发送什么、预计费用与影响范围 |
| 保存屏障 | 进入统一写入队列，等待在途保存完成并确认 CLEAN | 校验会话与草稿 revision | “正在保存…”；未完成不进入下一步 |
| 切换 | 提交目标模式、sessionRevision、baseRevision、expectedEpoch | 锁章节会话，递增 modeEpoch，撤销旧任务接受资格，记录模式事件 | 成功后提示“已切换到 AI 辅助模式”，面板按新能力渲染 |
| 失败 | 保留原模式与可恢复内容，不清空正文 | 返回冲突或权限原因 | 就地说明失败原因与可执行下一步（重试／比较／保存） |
| 多端 | 其他标签页刷新后看到新 modeEpoch | 会话状态为唯一真相 | 不同标签页不出现两个“当前模式” |

以候选接管是独立原子命令：客户端确认本地 CLEAN 后冻结输入，服务端在旧世代仍有效时校验候选与全部基线，同事务应用正文、来源、作者批准的记忆变化并递增世代；成功前不得把候选粘进编辑区，失败则保留原本地稿与候选供比较。空章首次建稿与候选接受共享同一章节锁，先有人建稿时旧候选不得再建第二份稿。

### 8.7 三模式 AI 能力矩阵

矩阵描述“各模式下默认开放到什么程度”，实际能力以服务端 `capabilities` 与会话状态为准；客户端不得用本地开关绕过服务端判定。

| 能力／行为 | 传统 MANUAL | AI辅助 ASSISTED | 纯AI AUTONOMOUS |
| --- | --- | --- | --- |
| 正文编辑 | 全量可编辑 | 全量可编辑，候选并排 | 任务运行期候选只读；接管后转可编辑模式 |
| 续写／改写 | 不提供 | 选区或指定段落，单次任务 | 按章节计划整章生成 |
| 校对与连续性检查 | 作者自查 | 可对指定范围发起 | 每章自动检查并进入有限修订 |
| 情节／人物建议 | 不提供 | 多个独立建议，不写正文 | 规划 Agent 生成章节计划，作者确认 |
| 世界观／人物设定 | 作者手动维护 | 可生成设定候选，确认后入记忆 | 记忆 delta 候选，接受时确认 |
| 摘要／记忆提取 | 手动整理 | 可申请提取单章 | 自动提取候选，作者确认后提交 |
| AI 插图 | 可上传合法图片 | 按需生成单图候选 | 可在批次内按场景生成候选 |
| 费用 | 0 | 每次任务前显示范围与上限 | 批次预算、步骤上限、实时归集 |
| 内容来源记录 | 作者输入与引用 | 人工＋AI 混合，逐次可追溯 | 主要 AI 生成，作者确认与修改可追溯 |
| 送审与发布 | 作者送审 | 同左，保留 AI 参与标识 | 同左，绝不自动公开 |

矩阵不表示“传统模式禁止作者粘贴外部文本”，而是传统模式不主动调用模型处理正文；作者粘贴的内容仍按来源与许可记录。

### 8.8 各模式编辑器行为细则

| 编辑器行为 | 传统 MANUAL | AI辅助 ASSISTED | 纯AI AUTONOMOUS（运行期） |
| --- | --- | --- | --- |
| 正文区 | 可编辑 | 可编辑，候选并排 | 只读候选预览，提供“接管编辑” |
| 输入与撤销 | 正常输入、撤销栈 | 正常；接受候选后合并撤销栈 | 运行期无输入；接管后恢复正常 |
| 自动保存 | 2 秒防抖／最长 15 秒串行 | 同左；接受前先完成保存屏障 | 不写本地正文，任务状态持久化 |
| 候选呈现 | 无 | 选区差异，替换／插入／另存 | 整章候选包＋冲突＋记忆 delta |
| 字数与统计 | 本地＋服务端确认 | 同左 | 候选统计与原稿统计并列 |
| 送审入口 | 保存至 CLEAN 后可用 | 同左 | 接受候选生成草稿后才可用 |
| 主要快捷键 | 保存、查找、预览 | 同左＋接受／拒绝候选 | 暂停、取消、接管编辑 |
| 失败表现 | 保留本地稿，提示恢复 | 保留本地稿与候选，锚点失效标 STALE | 任务失败可重试，绝不写正文 |

编辑器在三种模式下共用同一套保存、撤销、字数与无障碍基础设施；差异集中在“正文是否可编辑、候选如何呈现、接受后如何落稿”，不为纯 AI 另造一个编辑器内核。

## 9. AI辅助写作与插图

### 9.1 文本辅助动作

| 动作 | 默认输入 | 输出 | 应用规则 |
| --- | --- | --- | --- |
| 续写 | 光标前必要段落、章节目标、相关确认记忆 | 新段落候选 | 在冻结锚点插入，不覆盖全文 |
| 改写／润色 | 选区、作者指定语气及必要上下文 | 替换选区候选、差异摘要 | 校验选区hash与基线；作者接受才替换 |
| 校对 | 作者指定章／选区 | 错别字、称谓、时间冲突及证据 | 分项接受，事实冲突不能自动篡改设定 |
| 情节建议 | 当前提纲、未解决冲突、目标 | 多个独立建议 | 不直接写入正文或正典记忆 |
| 人物／世界构思 | 作者问题和明确参考 | 设定候选 | 转记忆前确认，标为作者采纳来源 |
| 摘要与连续性检查 | 指定已保存版本与允许来源 | 结构化摘要、矛盾、引用 | 摘要不是最终事实；修改记忆需确认 |

建议任务目标一次一项，候选返回包含artifactId、baseRevision、sourceRangeHash、providerModelVersion、inputManifest、warnings和provenance。流式文本只是预览，完整输出通过结构／安全校验后才出现接受按钮。

接受可选“替换／插入／新建备选”，默认最小改动。若用户输入已改变目标段落或切章，停止自动应用；可重新计算差异供确认，不能靠模糊字符串替换猜测位置。拒绝候选不写正文、不改变正式记忆，但保留最少运行审计与费用。

自动保存、普通接受和接管共用一个客户端写入队列。接受前短暂冻结输入，等待在途请求结束，并核对全稿localHash=confirmedServerHash及候选baseRevision；不能只检查选区，因为选区外也可能有未保存修改。存在DIRTY时先提示保存／比较，保存导致旧候选失效后必须重新确认新基线，禁止静默套用。条件接受成功后才更新本地正文、撤销栈与ETag；失败保留原本地稿和候选。新建备选只保存隔离artifact，不创建同章第二份EDITABLE稿。

### 9.2 插图生成流程

作者选场景／角色 → 选择已确认设定与合法参考图 → 指定用途（私有素材／封面候选／未来正文插图） → 展示供应商与预算 → 提交任务 → 隔离生成结果 → 类型、像素、hash、净化与内容检查 → 候选图库 → 作者选图与来源确认 → 私有素材资产 → 按用途走已有或扩展审核发布。

角色形象复用基于作者确认的文字设定、参考资产和版本，不承诺模型天然保持人物一致；每次输出都要比对关键特征并允许拒绝。禁止未经授权克隆可识别真人形象、生成违法或性化未成年内容；“小说配图”不是豁免。

### 9.3 与现有素材契约衔接

现有COVER／EVIDENCE上传不等于私有素材库或正文插图通道。封面候选须经平台侧受控入库／检查并生成可引用assetId，作者再修改WORK草稿并送审；不能把模型返回URL直接作为公开封面。

私有生成图与参考素材需要新增LIBRARY／GENERATED_IMAGE等候选用途及权限模型，名称待契约评审。不得挪用EVIDENCE用途存普通灵感图。正文插图因现有ChapterDraft只有纯文本body而暂不开放插入；P2扩展内容块、材料摘要、阅读器、审核与下架矩阵后再启用。

费用在任务开始前展示上限和计费单位，失败／取消是否收费按真实供应商规则说明。未商业化阶段可使用经批准的平台成本配额，不向用户伪装售卖积分；收费AI额度须商业专项批准。

## 10. 纯AI的workflow与multi_agent架构

### 10.1 架构责任

采用确定性workflow协调、多个窄职责Agent执行的模式，而非自由群聊。协调器负责状态、幂等、权限、预算、步骤上限和工具调度；Agent只返回结构化候选产物。

建议复用Java业务核心的身份、草稿、提交和审计；AI编排与推理适配作为隔离工作进程，可采用Python实现，具体框架和供应商SDK另行验证。本设计不依赖某个尚未安装的Agent框架能力，也不要求首版引入新微服务群。

```text
作者确认任务计划
  -> 业务API：权限/版本/预算/许可/幂等
  -> 持久workflow：任务状态、检查点、世代、重试
       -> 记忆编排器：确认事实 + 情节状态 + 来源版本
       -> 规划Agent -> 写作Agent -> 连续性Agent
                         -> 文风Agent / 安全预检（有界并行）
       -> 确定性汇总器 -> 有限修订 -> 候选包
  -> 作者比较正文、冲突和记忆变更 -> 受控接受到草稿
  -> 既有保存/送审/审核/公开链
```

该图是目标流程示意，不表示当前存在这些运行服务。安全预检不是平台正式审核，连续性Agent也不是记忆最终裁决者。

### 10.2 Agent职责与工具权限

| Agent／组件 | 输入 | 允许输出 | 工具权限 | 禁止 |
| --- | --- | --- | --- | --- |
| 记忆编排器（确定性为主） | work、branch、storyCutoff、memoryRevision、任务范围 | 有来源的上下文包、缺口、预算分配 | 读当前授权作品的版本化记忆和索引 | 跨作品搜索、用最新事实覆盖历史视角 |
| 规划Agent | 总纲、卷纲、章节目标、人物状态、伏笔 | 场景序列、人物目标、关键事件候选 | 只读本次上下文 | 直接更新正式提纲或记忆 |
| 写作Agent | 已冻结章节计划、上下文包、文风约束 | 完整章节候选与引用manifest | 只读批准素材；写隔离artifact | 更新draft／publication数据库 |
| 连续性Agent | 候选、正典事实、时间线、人物知情状态 | 冲突列表、来源、严重性、修正建议 | 只读确定范围记忆 | 因“更顺”自行改世界规则 |
| 文风Agent | 候选、作者自身样稿／获授权风格描述 | 重复、视角、节奏与用语建议 | 无外部浏览、只读授权输入 | 指定在世作者精确模仿或未经授权长段复刻 |
| 安全／来源预检 | 候选与来源manifest | 风险标记、引用疑点 | 调用批准的检测适配器 | 自行批准发布或宣称零侵权 |
| 记忆提取Agent | 已完成候选及上下文 | 待确认实体／事实／事件／伏笔delta | 只写候选artifact | 候选直接变正典 |
| 汇总与控制器（确定性） | 各检查结果、步数、预算 | 进入返工／阻断／等待作者 | 更新自身workflow状态 | 采纳Agent文本中提出的任意工具调用 |

同一模型扮演多个角色不构成独立安全保障；平台独立审核、人类确认与确定性约束不能省略。任务重放保留Agent定义、提示模板、模型、参数和工具版本，但不承诺随机模型逐字可复现。

### 10.3 单章执行步骤

| 步骤 | 完成条件 | 检查点 | 失败处理 |
| --- | --- | --- | --- |
| 1资格与冻结 | 身份、作品归属、模式、草稿、记忆、许可及预算可用 | inputManifest＋baseRevision＋modeEpoch | 拒绝或等待作者补齐；不调用模型 |
| 2记忆准备 | 必要人物／世界硬事实及前章状态可检索，索引水位可解释 | contextManifest＋sourceRevisions＋cutoff | 缺关键事实或索引未就绪则暂停，不伪造补齐 |
| 3章节计划 | 场景、视角、目标、时间位置、伏笔操作结构合法 | planArtifact＋schemaVersion | 有界重试；重大设定选择交作者 |
| 4撰写 | 完整输出并通过长度、编码和结构校验 | candidateArtifact＋hash | 超时／截断不能视为完整稿 |
| 5检查 | 连续性、文风、安全／来源结果齐全 | issueSet＋evidenceRefs | 检查失败不默认通过 |
| 6有限修订 | 按阻断项修订，且复检通过或转作者决定 | 每轮候选与issue版本 | 首版最多2轮自动修订，超限等待作者 |
| 7记忆候选 | 从最终候选提取且有对应段落来源 | memoryDeltaArtifact | 提取失败可查看文本，但不允许假称记忆已更新 |
| 8作者确认 | 正文、来源标识、未决问题和记忆delta已审阅 | acceptIntent | 拒绝或接管；不直接发布 |
| 9原子接受 | 当前草稿／模式／记忆／许可仍匹配 | 新draftRevision＋provenance＋memoryCommit | 任一冲突整体不应用，返回可比较的失效原因 |

首版以单章闭环为默认。小批量计划最多3章为候选上限，每章接受后才把该章新事实纳入下一章正式上下文；未确认时停止后续正式生成。后续“连续候选批次”必须使用隔离分支记忆，不能把未确认前章当已接受正典。

### 10.4 workflow状态机

任务状态是新领域状态，不与publication_workflow混用。

| 当前状态 | 允许事件 | 下一状态 | 约束 |
| --- | --- | --- | --- |
| QUEUED | 领取、取消 | RUNNING／CANCELLED | 校验租约、任务世代与有效权限 |
| RUNNING | 检查点完成、中途决策、最终候选齐备、可恢复故障、永久失败、取消请求 | RUNNING／WAITING_DECISION／WAITING_AUTHOR／PAUSED／FAILED／CANCEL_REQUESTED | 不允许直接SUCCEEDED或PUBLISHED |
| PAUSED | 资格重新校验后恢复、取消 | QUEUED／CANCELLED | 原快照过期时标STALE，不从新材料悄悄续跑 |
| WAITING_DECISION | 提交明确选择并继续、拒绝、取消、基线失效 | QUEUED／REJECTED／CANCELLED／STALE | 决定绑定decisionId与版本；不写正文／正典，不等于最终接受 |
| WAITING_AUTHOR | 接受、拒绝、失效、取消 | ACCEPTED／REJECTED／STALE／CANCELLED | 仅最终完整候选包进入；接受只有作者受控命令可触发 |
| CANCEL_REQUESTED | worker确认或平台隔离晚结果 | CANCELLED | 无论外部是否停止，接受入口已失效 |
| 任意非终态 | 模式／草稿／记忆关键版本冲突 | STALE | 必须新建或显式rebase后生成新任务，不覆盖旧输入 |
| ACCEPTED／REJECTED／FAILED／CANCELLED／STALE | 查看、从快照新建 | 原状态不变 | 终态不回退，不复用原运行身份修改结果 |

基础设施重试保留同一runId，步骤attempt递增；作者改提纲或重写要求属于新run，记录parentRunId。暂停是停止下一步派发，正在进行的外部请求可能仍产生成本；界面说明这一点。

WAITING_DECISION用于规划分歧、补充解释或有限修订后待处理问题。持久化decisionId、decisionRevision、暂停步骤、允许选项和待续步骤；作者提交选择时重验全部基线并记录决定，然后从指定检查点继续，不能重放已成功付费步骤。选择仅在原范围／原预算内可继续；修改已确认设定、提纲或增加修订轮数须新run。达到调用或返工硬上限时，只能拒绝、接管人工修改后重新检查，或另行批准新任务；中途确认不得重置上限或绕过硬冲突检查。

### 10.5 幂等、租约与副作用

run创建使用Idempotency-Key，作用域为主体＋作品＋操作；请求摘要包含modeEpoch、draftRevision、memoryRevision、参数和预算。同键不同载荷冲突。

步骤逻辑身份为runId＋stepKey＋inputHash；外部每次attempt有独立记录。支持供应商幂等时传递稳定请求身份；不支持且超时结果未知时标UNKNOWN并先查询／对账，禁止立即重复付费调用。无法查明时等待作者明确批准重试及新增上限，旧结果仍不可重复接受。

worker持有租约和fencingToken。结果回写校验租约世代、run状态、输入hash与对象hash；迟到结果可保留为隔离证据，不能覆盖新attempt或已取消任务。

### 10.6 预算与有界执行

创建任务前预留预算，预算包含输入／输出token、图像数量、供应商费用估计、重试余量和任务上限。模型调用前校验剩余额度；输出长度使用供应商支持的硬上限并验证实际计费，供应商不支持确定上限时不得宣称绝对不超支，应预留保守余量和账单告警。

首版运行限制候选：固定9个业务阶段（对应§10.3），最多2轮自动修订，并行外部检查最多2个，每作品1个写作批次。业务阶段不是调用次数：资格、作者确认、原子接受不消耗模型调用；检索若需外部embedding也计外部调用。单run最多16次外部调用尝试，包含失败、重试与UNKNOWN，不因等待／重启重置。

基准模型计划为规划1＋初稿1＋首轮检查3＋修订最多2＋两轮复检最多6＋记忆提取1，共14次；剩余2次只供已批准重试或外部检索开销，无法在余量内完成全部必要检查时停止，不跳过检查。未知结果重试仍按§10.5处理；不同供应商拆分更多调用时须先缩小计划或批准新上限。具体最大token、墙钟时长和人民币额度依据供应商实测与Owner预算冻结，不填未经批准价格。

已发生费用、预留费用、待确认费用、释放余额分开；取消不直接全额退回已消耗成本。额度与任务受理同事务或等价强一致预留，多个标签页不能并发透支。平台成本配额不等于向作者售卖余额，财务账本与AI成本账分别管理。

## 11. 长期记忆与小说一致性

### 11.1 记忆分层

| 层 | 内容 | 权威性 | 使用方式 |
| --- | --- | --- | --- |
| 创作约束／世界圣经 | 世界规则、叙事视角、不可违反设定、作者禁区 | 作者确认后为硬约束 | 每次生成优先装入必需子集 |
| 人物档案 | 稳定身份、外貌、性格、关系及别名 | 版本化确认事实 | 按参与人物和相关关系检索 |
| 人物时态状态 | 年龄／位置／伤势／持有物／知情信息随故事时间变化 | 与事件和章版本关联 | 查询到本章storyCutoff，不用未来状态覆盖过去 |
| 情节时间线 | 已发生事件、参与者、先后／因果、时间区间 | 来源正文与作者确认 | 防复活、瞬移、重复发生和因果错误 |
| 伏笔与承诺 | 埋设、预计回收条件、已回收事件、未决冲突 | 明确状态与证据 | 计划时提醒，不能自动宣称已回收 |
| 提纲与规划 | 总纲／卷纲／章纲、未来意图 | 计划，不是已发生事实 | 与已发生情节分通道输入 |
| 章节摘要 | 本章事件与人物变化的压缩表达 | 可失效的派生材料 | 节省上下文，不覆盖原文和硬事实 |
| 文风偏好 | 作者原创样稿、节奏、叙事人称、用词限制 | 作者许可与确认 | 辅助约束，不存未经授权仿作语料 |
| 运行工作记忆 | 当前计划、候选、临时判断 | 非正典、run隔离 | 仅该run使用，拒绝后不能污染其他任务 |

### 11.2 正典、计划与分支

每部作品拥有主创作分支MAIN及可选隔离备选分支。首版只开放MAIN和运行私有分支，不提供任意复杂Git式分支UI。正式创作记忆可包含作者已接受但尚未公开的章节，公开状态与创作事实状态严格分开。

作者确认的未来计划不得作为已经发生事件。例如第20章计划揭示身世，在第8章生成时只能作为作者规划约束，不能让人物提前知道秘密。上下文包分别提供authorPlan、storyFacts和characterKnowledge，标记storyCutoff、视角角色及允许剧透范围。

同一人物改名用稳定entityId与别名、有效区间表达；不要因名字相同合并两个角色。关系、阵营和性格变化通过事件和时态事实表达，不简单覆盖上一条value。

memoryRevision必须能还原完整快照，不仅还原fact：实体名称／别名、事件信息、伏笔状态及解决引用都采用不可变revision，memory_commit manifest指向各实体在该提交下的精确revision。查询冻结版本时禁止连接实体当前名称或伏笔最新状态。失效另记source invalidation记录与当前sourceEpoch，不篡改旧提交：历史审计可读旧快照并显示“当前已失效”，新运行则拒用该失效来源。

### 11.3 事实结构与冲突规则

每条事实包含主体entityId、谓词、结构化值、故事有效时间／章节范围、记录时间、来源revision＋段落锚点、可信状态、作者确认信息、supersedes引用及branch。这样区分“小说里何时成立”和“系统何时获知”。

硬冲突包括违反作者锁定世界规则、已死亡人物无解释出现、同一时间互斥位置、人物使用尚未知晓信息、伏笔已回收再次按未回收处理。软问题包括文风偏差、节奏建议、可能重复描写；不因软问题擅自改变情节事实。

来源优先级：作者明确锁定规则优先；已接受正文与作者声明不一致时创建冲突，不自动按较新时间覆盖；计划不能覆盖既成事实；模型推断只能是待确认候选。作者选择修订规则时生成新记忆版本及影响清单，不删除旧事实历史。

### 11.4 上下文组装

1. 验证作品／分支授权和memoryRevision，获取已确认硬约束。
2. 根据章纲列出参与实体、地点、时间、视角、伏笔和最近章节依赖。
3. 用结构化过滤读取这些实体在storyCutoff的事实与知情范围。
4. 读取最近已接受章节状态及对应摘要；摘要失效则回到受控原文范围或暂停补建。
5. 对作者批准的素材集合做关键词／语义检索，检索结果带来源和许可，不允许跨作品隐式召回。
6. 进行token预算分配，记录include／exclude清单、选择原因和缺口。
7. 若必需硬约束无法放入上下文，缩小任务／拆场景或等待作者，不静默截掉后宣称记忆完整。

向量索引按owner、work、branch、memoryRevision／sourceRevision和licenseScope过滤；服务端先确定允许集合再检索。不得先全库语义搜索再让模型自行忽略越权结果。索引落后时读取权威结构化数据或等待水位，不能以“召回没找到”推断事实不存在。

### 11.5 接受候选与记忆提交

候选接受命令携带sessionRevision、draftRevision（空章为空且expectedNoEditableDraft=true）、modeEpoch、memoryRevision、sourceEpoch、outlineRevision、candidateHash、已批准memoryDeltaIds及作者内容声明。客户端先执行§9.1共同写入屏障，服务端再次验证当前权限、许可证、运行状态、检查结果、完整性和所有基线。

按作品记忆头→章节会话→草稿／任务的统一锁顺序，同一业务事务内完成：创建或更新草稿revision、内容来源记录、推进作品sourceEpoch、memory_commit绑定新sourceEpoch、确认事实／事件引用、run变为ACCEPTED、审计与Outbox。已确认delta完整覆盖本次修改时更新coveredSourceEpoch，否则标NEEDS_REVIEW并阻止依赖生成。当前接受以事务前基线校验一次，不被本次事务自身推进的世代误判失效；其他旧run仍失效。向量索引和摘要派生更新异步进行，设置新的indexWatermark；失败不回滚已接受正文，但新生成在所需水位未满足前不得假装记忆可用。

作者可接受正文但拒绝某条事实推断；若该条为后续生成所必需，记忆状态标NEEDS_REVIEW并阻止依赖它的新run，不能强迫错误事实进入正典。重大冲突必须先解决或作者明确选择修订策略，不能只点“忽略全部”获得一致性通过。

### 11.6 人工改稿后的失效与修复

人工保存先保证草稿可靠，不因外部记忆提取／索引服务不可用丢失文字。但失效屏障不能只靠异步事件：保存事务按作品记忆头→章节会话→草稿的锁顺序，写正文时同步递增作品sourceEpoch、置覆盖状态PENDING并追加Outbox；该事务失败则保存整体失败，客户端保留未同步稿。

首版采用保守的作品级屏障：创建run、每次外部派发、中途继续和候选接受都核对冻结sourceEpoch；新run要求coveredSourceEpoch=sourceEpoch且所需索引就绪。这样即使失效事件未被消费，旧章修订也立即阻止后章旧候选接受。异步消费者再按来源依赖标记具体摘要／事实失效并重建，CAS确认没有更新的sourceEpoch后才能推进覆盖水位；后续可优化精确依赖，但不能先移除同步屏障。

MANUAL模式不自动调用模型重建；作者可手动更新记忆或主动启用一次受控提取。ASSISTED／AUTONOMOUS也需已有明确的自动提取许可；提取仍产生候选而非自动确认。无许可则提示等待维护，不偷发正文。

删除、调整章节顺序或修订早期事实时，按sourceRevision与dependsOn关系找到受影响的后章计划、摘要、候选和未执行任务，列出待复核范围。先失效再重建，不把所有后章无差别重写。已公开版本不跟随记忆修订被原地改写。

### 11.7 一致性指标与测试集

不承诺“永远记住所有内容”或“零幻觉”。目标是持久化、可检索、可追溯、可纠错，并用有金标的长篇场景证明一致性机制有效。

候选验收集至少覆盖20组故事，每组30章、固定人物／时间线／伏笔金标；另设100章压力样本检查上下文裁剪与索引恢复。全部使用合成安全内容，样本量为工程验证目标，不是当前已执行读数。

硬规则违规必须被确定性检查或审阅阻断；关键事实召回率、带正确来源的事实比例、未来信息泄漏数、接受后索引滞后、变更影响漏标数分别报告。模型质量门槛以试点金标统计冻结，不用一个平均分掩盖权限泄漏或硬冲突。

## 12. 数据模型设计

### 12.1 共通约定与实体关系

沿用MySQL8.4映射、服务端UUIDv4、UTC DATETIME(6)、lock_version乐观锁、外键RESTRICT、不可变版本和追加审计。以下为逻辑表设计候选，不是已存在数据库，也不是可直接执行迁移。

除专门说明的事件／不可变记录外，继承id、created_at、updated_at、created_by、updated_by、lock_version及适用的deleted_at。PII／合规材料采用受控加密与权限，不能把“cipher”列名当加密实现。

```text
user -> work -> chapter -> draft -> draft_revision_snapshot
                         -> creation_session -> ai_run -> ai_step / artifact
work -> outline_revision
work -> story_branch -> memory_commit -> entity / fact / event / thread
artifact -> candidate_memory_delta -> 作者确认 -> memory_commit
artifact -> provenance -> draft revision -> content_version
material_item -> material_revision -> asset / text -> licensed input manifest
consumption facts -> work_metric_daily / rank_snapshot -> author dashboard
```

### 12.7 保留、删除与恢复

草稿快照按§6.4有界保留；已接受内容来源、许可和必要审计按现有不可变内容及法律保全策略保留。未接受artifact候选建议30天过期，run脱敏元数据建议180天在线；这些是需法务／安全冻结的专项建议，不覆盖已有更严格保留要求。

删除未接受任务可先撤销展示与新引用，后台按许可、保全、费用对账和对象引用清理。删除一部作品的私有素材与记忆需同步向量索引、缓存和供应商删除请求；不能只删SQL主记录。备份恢复后重放撤权与删除指令，避免旧副本重新进入生成上下文。

### 12.9 迁移、回滚与数据归属策略

- **先加后接线**：新表以 V7+ 迁移先建（默认空、无入口），通过配置门控逐步接线；不修改 V1–V6 表语义，不做破坏性列变更。遵循 expand/contract，禁止锁表式大改。
- **前向迁移**：迁移脚本只向前，不提供自动 down；回滚以“停止写新表 + 保留数据 + 关功能门”实现，避免删除已产生的事实与费用记录。
- **回填有检查点**：指标可从历史消费事件重算（按日分区、可重跑、幂等）；记忆只从**已接受**章节与作者确认事实回填，不回填未接受候选，不把模型推测写入正库。回填任务记录进度、失败区间与重试次数。
- **归属单一**：正文、版本、流程、审核、账本仍归现有域；新域只拥有自己的表。跨域读取经 `foundation` 端口或只读投影，禁止双写与跨库事务。
- **容量有界**：草稿快照按 30 天／200 个检查点；未接受 artifact 30 天；记忆按 revision 增量存储，摘要与向量可重建；大对象进对象存储，不进 MySQL 行。

### 13.3 任务请求与响应示例

以下仅说明拟议载荷语义，ID为占位示例值，不是有效请求：

```json
{
  "kind": "CHAPTER_AUTONOMOUS",
  "workId": "<work-uuid>",
  "chapterId": "<chapter-uuid>",
  "sessionRevision": 9,
  "draftId": "<draft-uuid>",
  "baseRevision": 17,
  "expectedNoEditableDraft": false,
  "modeEpoch": 6,
  "memoryRevision": 42,
  "sourceEpoch": 58,
  "outlineRevision": 8,
  "chapterGoal": "主角发现线索，但仍不知道幕后人物身份",
  "contextScope": {"materialRevisionIds": [], "storyCutoff": "chapter-11-end"},
  "budgetCap": {"currency": "CNY", "amountMicros": 1000000},
  "maxRevisionRounds": 2
}
```

示例为已有草稿；空章请求传draftId=null、baseRevision=null、expectedNoEditableDraft=true，仍必须提供workId、chapterId、sessionRevision及其余适用基线。新作品无确认记忆时使用MAIN初始空提交，sourceEpoch与覆盖水位相等，必要创作设定在调用前由作者确认。

示例金额仅为结构示意，不是正式限额或价格。服务端检查参数不能超平台批准上限，用户不能通过传入更高轮数、工具名单或prompt取得更多权限。memoryRevision引用完整作品分支身份，不能只按数字跨作品查找。

202响应返回runId、state、acceptedInputVersions、reservedBudget与status路径；不返回“已写入正文”。所有错误遵守现有HTTP信封，新增业务原因需更新字典与契约，不在源码散落自造错误码。

### 13.4 并发、事件与事务集成

- 草稿保存与候选接受都由authoring拥有；AI worker无Repository直连权限。
- 记忆与来源接受首版保留在同一业务部署／数据库事务可控范围内，避免尚未证明必要的跨服务原子提交。
- 接受事务提交Outbox，索引和分析消费具有Inbox幂等；正文接受成功但索引失败时明确显示记忆待就绪。
- SSE不是事实源；重连用seq补齐，缺口或过期则回读任务快照。连接刷新需重新鉴权，撤会话停止后续流；不把token放URL查询参数或浏览器日志。
- 供应商回调验证来源和绑定，回调内容不直接转换成发布／记忆命令。

### 13.5 关键集成时序

以下为跨层协作的最小序列，用于接口编排与集成测试设计；箭头仅表达调用方向，不表示同步 RPC 全部落地。

**S1 自动保存**

```text
客户端 → GET /drafts/{id}                     200 {revision, state, content} + ETag
客户端    本地编辑 → DIRTY → 防抖2秒或连续编辑15秒
客户端 → PUT /drafts/{id}  If-Match:"etag" + Idempotency-Key
服务端    authoring：归属 → EDITABLE → If-Match → 正文校验 → revision+1
服务端 ← 200 {revision, state, content} + 新 ETag
客户端    只更新对应快照基线 → CLEAN；失败按 §6.3 场景表处理
```

**S2 送审与发布状态**

```text
客户端    保存至 CLEAN → 预览快照（作品/章/字数/来源声明）
客户端 → POST /drafts/{id}/submissions  If-Match + Idempotency-Key
publication  SubmissionGate → 正文对象写入 → 同事务五写：
             content_version + publication_workflow + Outbox(ContentSubmitted.v1)
             + audit_record + draft=SUBMITTED
服务端 ← 202 受理（不是“已发布”）
moderation  消费 ContentSubmitted.v1 → 建 review_case → AUTO_REVIEW
moderation  终局 → Outbox(ReviewResolved.v1)
publication 消费 ReviewResolved.v1 → 状态机裁决 → 指针原子交换 + ContentPublished.v1
作者端      AW-05 回读 workflow 与通知，显示通过／驳回／申诉入口
```

**S3 纯 AI 任务运行**

```text
客户端 → POST /author/ai-runs  各基线 + 预算上限 + 章目标
服务端 ← 202 {runId, state=QUEUED, acceptedInputVersions, reservedBudget}
orchestrator  租约领取 → RUNNING → 资格冻结/记忆准备/计划/撰写/检查/修订/记忆候选
每步      → ai_run_event(seq) → SSE 推送（脱敏进展 + artifact 引用）
遇到分歧  → WAITING_DECISION（decisionId + 允许选项）
候选齐备  → WAITING_AUTHOR（正文候选包 + 冲突 + delta + 费用）
```

**S4 候选接受**

```text
客户端 → POST /author/ai-runs/{id}/acceptances  candidateHash + session/draft/
          mode/memory/source/outline 各基线 + 已批准的 deltaIds + 内容声明
authoring  锁顺序：work_memory_head → creation_session → draft
同事务    draft revision/内容、content_provenance、memory_commit（绑定新 sourceEpoch）、
          run=ACCEPTED、其他旧任务失效、audit、Outbox
异步      memory_index_job / 摘要重建 → 新 indexWatermark
新任务    要求 coveredSourceEpoch=sourceEpoch 且所需索引就绪，否则暂停而非假装已记住
```

### 13.6 事件与消费者

事件沿用 `foundation/event` 信封（eventId、eventType、aggregateId、aggregateRevision、payload、occurredAt）；消费者必须 Inbox 幂等，生产者 Outbox 至少一次。标注 `*` 的为拟议事件，需版本化字典评审后启用。

| 事件 | 生产者 | 消费者 | 用途 | 状态 |
| --- | --- | --- | --- | --- |
| ContentSubmitted.v1 | publication | moderation | 建审核案件、触发机审 | 现有 |
| ReviewResolved.v1 | moderation | publication | 终局裁决 → 发布／驳回 | 现有 |
| ContentPublished.v1 | publication | engagement（通知）、analytics* | 追更通知、发布统计 | 现有（分析消费拟议） |

### 15.2 性能候选目标

专项首版建议：本地输入响应p95<50ms（定义固定测试设备与100000字符样本）；在线保存API p95<800ms（不含主动防抖）；已就绪指标查询p95<1500ms；任务受理API p95<1000ms（不含生成）；SSE状态从持久事件到可见p95<3秒。

这些是作者工具新增候选预算，不放宽原读者API与首屏门槛。模型生成时长按模型、token与图像档位分别测量并显示预估范围，不能统一承诺“几秒写完一章”。

### 15.3 监控与故障处理

监控保存成功率／冲突率／未同步时长、草稿恢复、指标水位、任务队列时长、步骤失败、UNKNOWN调用、实际费用偏差、记忆失效数量、索引滞后、候选接受冲突和版权撤权漏处理。

工作流数据库或对象存储不可用时停止接受新有费任务；记忆读取不完整时暂停依赖生成；供应商故障时保留手写与合法已保存数据，不切换到未经批准的外部供应商发送私稿。

恢复从已确认检查点继续，不重新调用所有成功步骤；恢复前复核权限、许可、预算和modeEpoch。备份必须覆盖workflow、记忆事实、来源引用和受控对象，恢复演练验证引用hash及撤权指令不丢。

### 15.4 安全工程约束

提示注入防护依赖工具边界而非提示词宣誓。用户正文、素材、检索命中、模型输出、回调均为数据；不能获得shell、任意URL读取、数据库写权限、发布权限或跨作品检索权限。

上传执行真实类型、像素、尺寸、解码与净化检查；模型结果按严格schema校验，未知字段不转命令。输入与输出经过敏感信息过滤及用途检查，脱敏不足时不发送供应商。

日志与追踪保留hash、ID、耗时和错误类别，正文／图片／许可原件放受控证据存储。禁止把生产私稿用于普通开发测试或将代码／内容自动上传第三方扫描平台。

| 第三批 | AWT-09～11 | 一项辅助动作从请求到差异接受；一条“改早章→失效→重建→新生成不用旧事实”的记忆链通过 | 不做长篇批量与自动发布 |
| 第四批 | AWT-12～13 | 纯 AI 单章从计划到原子接受；一张合法封面候选走完整检查与送审 | 不做连续批次与正文插图 |
| P2 专项 | AWT-14～17 | 按真实使用数据分别立项，逐项满足对应治理／商业／契约门禁 | 不把收益、评论、正文图、协作捆成一个大版本 |

每个批次必须交付：用户可完成的任务、实现范围、契约影响、迁移与回退、权限与版权说明、真实测试证据、未验证事项。只有页面、表结构或生成样稿，不算完成。

### 17.2 质量证据

每项记录实际命令、版本、环境、数据来源、通过／失败、前后业务行、Outbox、审计与费用差异。AI质量评估保存输入版本、模型、参数、金标和输出摘要；不能只截图“生成成功”。

基础功能使用真实MySQL验证锁、唯一性、事务和持久化；供应商适配先契约夹具再授权沙箱，费用与回调未知情况必须有真实边界测试。Web测试之外完成浏览器交互；原生能力使用真实平台工具与设备，不以网页嵌套代替。

权限与内容安全硬失败、自动保存丢稿、未确认写入、记忆越权／污染、预算并发透支均阻断上线。模型文风不佳可作为质量迭代，但不得以降低硬规则门槛换取产出率。
