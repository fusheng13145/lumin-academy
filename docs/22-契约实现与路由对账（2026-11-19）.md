## 5. 结论

1. **P0 契约覆盖 63/63（100%）。** 已实现覆盖文字主链、作者工作流、审核裁决与读取面、治理措施与读取面、配置审计、身份建档/角色读取、年龄/监护与分类；缺失为 0。
2. **审核/治理读取面 6 个端点已接入。** 案件详情/受控材料、限制列表/详情、申诉列表、分类列表均有路由；新增 15 个服务层用例（案件 5、限制 3、申诉 3、分类 2、审批追加 2）与 6 个 standalone MockMvc 接口用例（信封/ETag/no-store/分页/404）；增量四十一补 `getDraft` 3 个用例，增量四十二补作者读取面 4 个 HTTP 用例，增量四十三补过期限制 3 个用例，增量四十四补作者列表分页 6 个用例，增量四十五补审核队列分页 3 个用例，增量四十六补审核写回执 2 个用例，增量四十七补限制写回执 1 个用例，增量四十八补限制提案必填拒绝 1 个用例，增量四十九补审核队列裁决批量分组 1 个用例，增量五十补审核队列年龄带批量读取 1 个用例，全量 3582 用例 0 失败/0 错误。
3. **审批追溯统一经 `ProposalReviewStore`。** `proposal_review` 的 Mapper/Row 归 foundation，业务模块只注入 Store；依赖校验恢复 0 非法边、0 环。
4. **20 条契约外路由已逐条初判但未入契约。** 7 条 AI、5 条书架/历史归后置或 M1；内部 `PUT /internal/asset-objects` 标注 internal；legal-hold、限制撤销、auth sessions、closure 归 P0 治理/身份但冻结契约未收录，需评审后补登；在此之前不能计入 P0 契约覆盖。
5. **基线已形成棘轮。** 后续新增/删除路由或补齐缺口时，`--check` 会失败并提示更新基线，避免“代码悄悄偏离契约”。
6. **`getDraft` 已对齐契约 `DraftView`。** `data` 为 `id/revision/state/content`，WORK/CHAPTER 分别输出 `WorkDraft`/`ChapterDraft`；`DraftReadApiTest` 验证嵌套 JSON 与 ETag。`listMyWorks`/`listMyChapters` 仍是数组，且状态枚举含 `REMOVED/TERMINATED`，与 `AuthorWorkPage`/`AuthorChapterPage` 的分页和枚举不一致，未在本轮改动。
7. **作者读取面已有直接 HTTP 用例。** `AuthorReadApiTest` 验证 `getMyWork` 的 ETag 与 `B2004`→404、`listMyDrafts`/`listMyPublicationWorkflows` 的 `{items,nextCursor}` 信封；仍未覆盖真实 Mapper/SQL。
8. **过期临时限制不再计为生效。** `selectActiveKinds` 已加 `expires_at IS NULL OR expires_at > now`；`ActiveRestrictionsAdapterTest` 验证传时与 scope，`GovernanceIntegrationTest` 新增真实库用例（本机跳过）。`IN_REVIEW` 持久化与到期自动恢复仍未实现。

## 7. 边界

本文件只证明“注解层面的路由与 operationId 对应关系”。以下不在本文件证据范围：

- 运行时是否装配、是否被 Security 过滤器拦截；
- 请求体/响应是否符合 schema、错误码与 ETag/幂等语义；
- 业务验收、真实数据库事务、三端旅程、供应商与容量。
