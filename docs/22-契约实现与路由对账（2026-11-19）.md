## 5. 结论

1. **P0 契约覆盖 57/63（90.5%）。** 已实现集中在文字主链、作者工作流、审核裁决、治理措施、配置审计、身份建档/角色读取与年龄/监护；缺口仅剩审核/治理读取面 5 个与分类 1 个。
2. **作者工作流 7 个缺口已补齐。** `getMyWork`、`listMyDrafts`、`listMyPublicationWorkflows`、`changeWorkLifecycle`、`discardDraft`、`getWorkflow`、`cancelWorkflow` 已接入；草稿/流程列表使用签名游标，详情使用 ETag，撤回/丢弃使用 If-Match + Idempotency-Key。16 个服务层单元用例通过，接口级集成证据待补。
3. **20 条契约外路由不是“已完成”。** AI、书架、阅读历史属于后置/M1；auth/closure/legal-hold 属于 P0 但未进入冻结契约。UGC-026 通过前必须逐条分类：补契约（需评审）或明确 internal/后置。
4. **基线已形成棘轮。** 后续新增/删除路由或补齐缺口时，`--check` 会失败并提示更新基线，避免“代码悄悄偏离契约”。

## 6. 复跑方式

```bash
# 查看完整矩阵（Markdown）
python libs/tools/route_contract_matrix.py --format md

# 与基线比对（有漂移退出码 1）
python libs/tools/route_contract_matrix.py --check

# 经评审后更新基线
python libs/tools/route_contract_matrix.py --write-baseline
```

`scripts/verify-local.sh` 已加入 `--check` 步骤；契约文件 SHA256 变化时直接失败，必须先走契约评审。

## 7. 边界

本文件只证明“注解层面的路由与 operationId 对应关系”。以下不在本文件证据范围：

- 运行时是否装配、是否被 Security 过滤器拦截；
- 请求体/响应是否符合 schema、错误码与 ETag/幂等语义；
- 业务验收、真实数据库事务、三端旅程、供应商与容量。
